# astrocarto

Astrocartography SPA. Birth data → planetary lines on an orthographic globe,
three theme overlays, ASC/MC/whole-sign houses, all computed client-side
(nothing leaves the browser). Deployed to GitHub Pages via Actions.

Spec lives in `poc/` — start there for the "why," not here. `poc/README.md`
and `poc/reference/README.md` index it:

- `poc/ENGINE-SPEC.md` — computation. Math, houses, scoring.
- `poc/UX-SPEC.md` — presentation. The "Void" globe-as-product design.
- `poc/reference/void-components.html` — primary UX reference (ported into `src/components/Globe.tsx`, `App.tsx`, `Sheet.tsx`).
- `poc/reference/time-scrubber.html` — scrubber/teaching reference. **Not yet ported** — see Open below.
- `poc/astrocarto.py` + `poc/golden.json` — Swiss Ephemeris oracle for ra/dec/lines/retrograde.
- `poc/golden-chart.json` — second oracle (pyswisseph) for ASC/MC/houses/signs/retrograde-speed. Joined to `golden.json` by case name for birth lat/lon/tz.

## Current architecture

Single-route state machine in `App.tsx`: `entry → resolving → field`, with
PLACE/DERIVATION/PRECISION/SHARE as one shared `Sheet` (`src/components/Sheet.tsx`,
content in `SheetContent.tsx`). The globe (`src/components/Globe.tsx`) is
`d3-geo` `geoOrthographic`, persistent across all states — drag, fly-to, a
single blurred-stroke heat line, label dodge, staggered reveal. Progressive
birth input lives in `BirthField.tsx`.

Math core in `src/lib/astro/`: `ephemeris.ts` (positions + analytic
retrograde/speed), `lines.ts` (AC/DC/MC/IC), `chart.ts` (ASC/MC closed-form,
whole-sign houses, aspects), `dignity.ts`, `time.ts`. `computeChart(utc, lat, lon)`
in `index.ts` is the single entry point.

Two independent conformance fixtures, no shared code path with the app:
`conformance.test.ts` (against `golden.json`) and `conformance-chart.test.ts`
(against `golden-chart.json`). `chart.test.ts` and `globe.test.ts` are
self-consistency tests (geometric identities, not an external oracle) for the
parts neither fixture covers.

Gazetteer (`src/lib/gazetteer/cities.ts`) carries a build-time-resolved
`wikiTitle` per city (`scripts/resolve-wikidata.mjs`, GeoNames → Wikidata →
enwiki title) — `src/lib/wiki/summary.ts` does the runtime `page/summary`
fetch. Never name-match a city to a Wikipedia article at runtime; see
UX-SPEC §7 for why (the "Kingston" collision).

Scoring (`src/lib/scoring/score.ts` + `public/data/weights.json`, generated by
`scripts/build-weights.mjs`) already matches ENGINE §6 — negative weights for
malefics, per-theme config, no restructuring needed. `src/lib/theme/copy.ts`
derives both the FIELD headline/lead copy and which lines actually draw
(`topKeysForTheme`, top 8 by `|weight|`) from that config, not a hardcoded
per-chart list.

## Open

- **Time/latitude scrubbers** (UX-SPEC §8) — not built. `poc/reference/time-scrubber.html`
  is a real, working reference for this (live recomputation, cusp warning,
  bloom-off-while-scrubbing) and has not yet been read/ported — do that before
  building this from scratch.
- **DERIVATION's on-globe geometry** — the sheet currently shows the numeric/
  formula breakdown only (sign, house, dignity, RA/dec, the line formula).
  UX-SPEC §8's table (horizon plane, orb circle, ascending-degree marker drawn
  on the globe itself) isn't implemented.
- **Line tweening on birth-data edit** — UX-SPEC §6 wants edits to animate
  lines to their new position rather than snap; currently snaps.
- **Reveal-time prefetch** (UX-SPEC §7 privacy note) — prefetching the top six
  candidate places' Wikipedia summaries at reveal, to blur which one was
  actually tapped. Not implemented; each PLACE fetch currently happens only
  on demand, which is a smaller but real signal leak.
- **Aspects** — computed (`chart.ts` → `Chart.aspects`) and conformance-tested,
  but not surfaced anywhere in the UI yet.
- **Voice typeface** (UX-SPEC §3) — reference files use proprietary Optima;
  the shipped fallback stack (`Optima, Candara, "Palatino Linotype", Palatino, serif`)
  is untested against a self-hosted alternative. Not blocking.

## Resolved

- **Mobile** (UX-SPEC §12) — no scroll on any viewport; line density capped to
  the active theme's top 8. Verified at 380×780 with a live browser run, which
  also caught two real bugs (bottom-control collision with the birth-summary
  line; native text-selection fighting the globe drag) — see `src/App.css`.
- **Retrograde detection** — was a 0.5-day finite difference sitting below the
  ephemeris's own error bound (read noise, not motion); now an analytic
  ecliptic-longitude rate from the geocentric state vector, verified against
  `golden-chart.json`'s signed `speedDegPerDay` per body — including
  `sydney_2001`'s Jupiter, a real station at −0.000339°/day.

## Interaction bugs already solved when this was ported from the reference files

From `poc/reference/README.md`, all three look like "nothing happened" bugs:

1. Full-bleed overlay must be `pointer-events: none`; only interactive leaves
   opt back in with `pointer-events: auto`.
2. Don't call `setPointerCapture` on `pointerdown` — it retargets the
   synthesized `click` and kills child `onclick`. Capture only after a
   movement threshold.
3. Don't redraw on `pointerup` before `click` fires — a full imperative
   teardown detaches the click's target node. (React's declarative
   reconciliation with stable keys avoids this bug class outright, as long as
   nothing does a manual `innerHTML = ''`-style rebuild.)
