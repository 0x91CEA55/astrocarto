# ENGINE-SPEC.md

Computation only. No rendering, no layout, no copy. Pairs with `UX-SPEC.md`.

Scope: birth input → planetary positions → astrocartography lines → chart
(signs, angles, houses, aspects) → theme scores. Everything here is closed-form
and deterministic: same input, identical output.

---

## 1. Stack

| Concern | Choice | Why |
|---|---|---|
| Ephemeris | `astronomy-engine` | ±1 arcmin ≈ 1.8 km line error, irrelevant vs 250 km orb. MIT. No data files. |
| Timezone | `tz-lookup` → IANA, `luxon` for offset | Historical DST is the top correctness risk. |
| Gazetteer | GeoNames `cities15000`, prebuilt | No key, no rate limit, doubles as scoring input. |
| Geometry | `d3-geo` | Already needed for rendering; reuse its projection maths. |

Swiss Ephemeris WASM only if asteroid points (Juno, Chiron) become required. It
carries AGPL/GPL — decide before writing code, not after.

`astronomy-engine` has no lunar node and no obliquity accessor. Compute mean
node and obliquity from IAU polynomials, or drop the node.

---

## 2. Time

Local wall clock + IANA zone → UTC → Julian Day.

Implement Julian Day **independently of the ephemeris library** (Meeus). A
`jd_ut` mismatch then can only be a timezone bug, never an ephemeris bug. This
diagnostic separation is load-bearing.

Never hand-roll offset tables. Delegate to tzdata via luxon.

---

## 3. Positions

Apparent geocentric, equator-of-date and ecliptic-of-date, matching Swiss
Ephemeris defaults.

`Equator()` is topocentric and needs an `Observer` — do not use it with a dummy
observer. Parallax reaches ~1° for the Moon, moving Moon lines ~100 km. Take the
EQJ vector from `GeoVector`, rotate to EQD, then read RA/dec.

**Retrograde detection is currently unsound.** A 0.5-day finite difference is
below the engine's own ±1 arcmin error for every outer body (Jupiter moves
0.000244° over that window; error bound is 0.0167°). It reads noise. Either
derive apparent longitude rate analytically from state vectors, or drop the flag
— it feeds nothing in the line maths.

## 4. Lines

```
GST  = Greenwich apparent sidereal time, degrees

MC:  λ = wrap180(α − GST)
IC:  λ = wrap180(α + 180 − GST)

c = −tan φ · tan δ
|c| > 1  → no line at this latitude (circumpolar)
H = acos(c)
AC:  λ = wrap180(α − H − GST)
DC:  λ = wrap180(α + H − GST)
```

`wrap180(x) = ((x + 180) mod 360) − 180`

**Convention: in-mundo** (physical body on the horizon/meridian). The
zodiacal-ASC variant gives different curves at high latitude. Neither is
correct; this is a spec choice. State it in the UI, don't relitigate it in issues.

Emit as GeoJSON `MultiLineString` so `d3-geo` handles projection and clipping.

## 5. Chart

### Angles — closed-form, no house library

Verified against Swiss to 1.09″ (ASC) and 0.93″ (MC):

```
RAMC = GST + longitude
ε    = IAU mean-obliquity polynomial

MC  = atan2(sin RAMC, cos RAMC · cos ε)
ASC = atan2(cos RAMC, −(sin RAMC · cos ε + tan φ · sin ε))
      + 180° if (ASC − MC) mod 360 > 180
```

### Houses — whole-sign only

House 1 = the ASC's whole sign. Each following sign is the next house.

No toggle, no setting, no second system. Rationale if ever reopened: Placidus
requires an iterative solve and **fails outright above ~66.5° latitude** (Swiss
returns an error, not a degraded result). Whole-sign needs only the ASC and
works everywhere.

Consequence: under whole-sign the MC is not necessarily the 10th cusp. Across
4000 sampled births it lands in house 10 only 68% of the time (9: 15%, 11: 15%).
The engine should expose the MC's house; copy rules live in UX-SPEC.

### Signs, dignity, aspects

Sign from ecliptic longitude. Essential dignity from a static table — flags line
strength, carries no interpretation.

Aspects: arithmetic on longitudes already computed. Orbs 8° conjunction and
opposition, 6° sextile, square, trine.

## 6. Scoring

Per theme, a weighted sum over lines with Gaussian falloff:

```
score(lat, lon) = Σ  weight[lineKey] · exp(−(km/σ)²) · dignityMultiplier[body]
```

- σ ≈ 200 km. Weights and σ ship as **JSON config**, not constants — they are
  conventions and will be tuned.
- **Negative weights for malefics on the same angle.** This is what makes a
  clean benefic outscore one sitting next to Pluto, and it is the whole
  "why is this place good" signal.
- Precompute line longitudes **per latitude row**, not per cell.
- Track the largest-magnitude contributor per point. That attribution is the
  input to the UI's explanation layer.

## 7. Conformance

`golden.json` — 6 births × 44 lines × 9 latitudes, generated by the Python
reference (`astrocarto.py`, Swiss Ephemeris).

Tolerances: `jd_ut` 1e-6 d · RA/dec 0.017° · line longitude 0.05°.

Cases are traps, not happy paths:

| case | trap |
|---|---|
| London 1969 | UK ran UTC+1 year-round 1968–71 |
| NYC 1954 | pre-1966 US DST was set locally |
| Berlin 1945 | wartime summer time, UTC+2 |
| Reykjavik Dec | high latitude — several lines must return `null`, not `NaN` |
| Sydney 2001 | southern DST; local and UTC dates differ |

Check `jd_ut` before blaming the ephemeris.

**Also assert `retrograde` and `dignity`.** The fixture carries both and the
suite ignores them; that is how the retrograde bug in §3 survived 318 green
tests.

Add: ASC/MC assertions, and a test that every theme yields a non-empty rendered
path at the default globe rotation.

Pin the CI Node version. Historical zones degrade silently on a small-ICU build.

---

## 8. Not deterministic

Out of scope for this layer, and not solvable by more code:

- **Interpretation.** The engine emits "Venus-DC passes 5 km from Ventura." That
  this means *partnership* is convention.
- **Orb threshold.** 250 km is arbitrary. Biggest lever on results.
- **Birth time accuracy.** Everything downstream of the UT anchor is exact;
  everything upstream is trust. Four minutes of error moves MC/IC a full degree.
